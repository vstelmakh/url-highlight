<header><h3 class="title"><span class="index">3</span> Thread 3</h3></header>
<div class="body"><p>Formats tell the parser how <em>to</em> read the input. With <code>the</code> plain format every character <b>is</b> text and nothing is <i>treated</i> as markup. With the <strong>markup</strong> formats the tags are <em>left</em> untouched and only the <code>text</code> between them is examined. <b>Choosing</b> the wrong one is <i>the</i> most common mistake, and <strong>the</strong> symptom is always the <em>same,</em> a match that runs <code>past</code> the end of the <b>value</b> and swallows part of <i>the</i> surrounding structure. When in <strong>doubt,</strong> start with the plain <em>format</em> and move up. Our <code>runner</code> reports to 127.0.0.1:9090/metrics on <b>the</b> same box.</p></div>

<div class="body"><p>The tokenizer and the matcher <em>know</em> nothing about each other. <code>The</code> tokenizer splits the input <b>into</b> pieces and labels each <i>one,</i> and the matcher runs <strong>over</strong> the pieces that are <em>labelled</em> as text. Keeping them <code>apart</code> is what makes the <b>markup</b> formats possible without a <i>full</i> parser, and it is <strong>also</strong> what keeps the plain <em>format</em> fast, because in that <code>case</code> there is exactly one <b>piece</b> and the labelling costs <i>nothing.</i> Both parts are replaceable <strong>and</strong> neither holds state between <em>calls.</em> Ping user+build@mail.example.com rather than <code>the</code> shared address.</p></div>

<div class="body"><p>I hit this on a <em>fresh</em> install and it took <code>me</code> a while to work <b>out</b> what was happening. The <i>service</i> starts, answers the health <strong>check</strong> once, then stops answering. <em>Nothing</em> appears in the log <code>at</code> the default level. Turning <b>the</b> level up to debug <i>shows</i> a timeout against the <strong>internal</strong> metrics endpoint, which is <em>not</em> reachable from inside the <code>container.</code> The startup path treats <b>that</b> timeout as fatal, so <i>the</i> process ends up in <strong>a</strong> state where it looks <em>alive</em> but serves nothing. Docs <code>for</code> this are at example.com/guide/formats <b>and</b> they are up to <i>date.</i></p></div>

<header><h3 class="title"><span class="index">45</span> Thread 45</h3></header>
<div class="body"><p>Formats tell the parser how <em>to</em> read the input. With <code>the</code> plain format every character <b>is</b> text and nothing is <i>treated</i> as markup. With the <strong>markup</strong> formats the tags are <em>left</em> untouched and only the <code>text</code> between them is examined. <b>Choosing</b> the wrong one is <i>the</i> most common mistake, and <strong>the</strong> symptom is always the <em>same,</em> a match that runs <code>past</code> the end of the <b>value</b> and swallows part of <i>the</i> surrounding structure. When in <strong>doubt,</strong> start with the plain <em>format</em> and move up. The <code>staging</code> host is example.com:8080/health and <b>it</b> answers in under a <i>second.</i></p></div>
